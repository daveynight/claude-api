# Building with the Claude API

Anthropic Academy course notebook, worked through lesson by lesson. It is also where we build tooling meant to be reused in other projects.

## Layout
- `claude_api.ipynb`: course notebook, one `### Lnn:` heading per lesson. Setup and helper cells come first, then the intro cells (no heading), then lessons in order. Define each function once; give lesson-specific functions distinct names (`run_aws_prompt`, `run_meal_prompt`) rather than redefining.
- `prompt_evaluator.py`: reusable `PromptEvaluator` (dataset generation, model-graded evals, HTML report). Not part of the course files; we wrote it for L15.
- `dataset.json`: AWS task dataset used by L11-L14. Generated by the notebook and gitignored, so a fresh clone regenerates it; re-running the generate cell overwrites the local copy. L15 uses `meal_dataset.json`.
- `.env`: `ANTHROPIC_API_KEY`, loaded with `python-dotenv`. Never commit it.

## Conventions
- Coursework code stays in the notebook. Only deliberately reusable tooling (`PromptEvaluator`) lives in an importable `.py` module with no notebook dependencies.
- Cells that generate datasets only do so when the file is missing; delete the file to regenerate.
- Use sync code with `ThreadPoolExecutor` for concurrency, not asyncio. Notebooks already run an event loop.
- Eval and grading calls use Haiku (`claude-haiku-4-5`); the lesson chat examples use Sonnet.
- Ask for JSON with the prefill `"```json"` plus stop sequence `"```"`, then `json.loads`. Haiku only: Sonnet 5.5 rejects prefill, so there ask for "only the JSON" and strip any code fence before `json.loads`.
- `chat()` returns the whole `Message`; use `text_from_message()` for the text. `add_user_message`/`add_assistant_message` accept a string, a block list, or a `Message`.
- Generated artifacts (`dataset.json`, `meal_dataset*.json`, `output.html`, `report_*.html`) are outputs, not source, and are gitignored.

## Secrets
- `tools/git-hooks/pre-commit` blocks staged `.env`/key files and secret-looking strings (it prints file names only). It is active via `git config core.hooksPath tools/git-hooks`; that setting is per-clone, so re-run it after cloning.
